Technical Note · Post-Training & Evaluation

Which Post-Training Stage Teaches a Model Whose Instructions to Obey?

Stagewise reasoning-mode source binding and confounded swap placebos across the Llama-3.1-Tulu-3-8B checkpoint lineage

Rajarshi Ghoshal GitHub Repository & Locked Configs
Summary

Instruction-tuned language models routinely face competing directives from different channels: a user's prompt asks for a terse answer while a retrieved document or working note calls for step-by-step verification. Binding too weakly to the user channel leaves a model open to indirect prompt injection from retrieved text, whereas binding blindly can override valid task constraints in context. Comparing only a pretrained base model against a final chat checkpoint hides which post-training stage installs this source priority, and hides whether outcome-driven reinforcement learning (RLVR) reinforces or erodes user obedience when obeying the user hurts task accuracy.

Across all four released checkpoints of Llama-3.1-Tulu-3-8B (Base → SFT → DPO → RLVR) on 1,319 held-out GSM8K test problems, direct preference optimization (DPO) introduces nearly the entire shift toward obeying the REQUEST block (ψ = −2.15), whereas supervised fine-tuning (SFT) barely moves source preference (ψ = −0.21 vs. −0.02 at Base). Subsequent RLVR training retains strong REQUEST priority (ψ = −1.68, net Base-to-RLVR shift Θ = −1.654, paired-bootstrap 95% CI [−1.669, −1.638]) while pulling +0.47 logits back toward reasoning on math problems where skipping chain-of-thought costs reward. We also show algebraically and empirically why standard source-swap placebos self-confound via (w_request − w_notes)(d_1 − d_2) whenever a checkpoint privileges one channel.

1. Experimental Design

Each GSM8K problem is formatted in a shared plain-text prompt (no chat template at any checkpoint) containing two instruction blocks, REQUEST and WORKING NOTES, that give opposite directives on whether to reason step-by-step before answering: 

PROBLEM:
<question>

REQUEST:
<directive for this source>

WORKING NOTES:
<directive for this source>

MODE CHOICE:
1 = begin with 1, then write a non-empty REASONING: section ...
2 = begin with 2, then write FINAL: followed by only the answer ...
Start your response with 1 or 2, then continue in that mode.
CHOICE:

At the CHOICE: token position, we read the pre-generation log-odds margin S = logit("1") − logit("2") between step-by-step reasoning (1) and answering directly (2). Every item is scored under four counterbalanced conflict prompts: request_cue (reasoning in REQUEST, direct answer in WORKING NOTES) and notes_cue (directives swapped), crossed with both block orders (request_first and notes_first). Averaging S(notes_cue) − S(request_cue) across items and both orders defines the stagewise binding contrast ψ(stage), where more negative values mean stronger REQUEST control, and Θ = ψ(RLVR) − ψ(Base) measures the cumulative post-training shift.

2. Stagewise Trajectory: DPO Installs Request Priority, RLVR Pulls Back

Direct preference optimization accounts for nearly all of the REQUEST binding observed in Tulu 3 8B, while SFT produces only a minor tilt and RLVR partially relaxes DPO's obedience across the 1,319-item GSM8K test split:

Table 1. Confirmation-split stagewise binding contrast (N = 1,319 GSM8K test items, averaged over request_first and notes_first).
Stage Checkpoint ψ = S(notes) − S(request) Stage step Δψ Behavioral reading
Base Llama-3.1-8B −0.02 — Indifferent between REQUEST and WORKING NOTES headers
SFT Tulu-3-8B-SFT −0.21 −0.19 Small tilt toward REQUEST
DPO Tulu-3-8B-DPO −2.15 −1.94 Installs dominant REQUEST priority
RLVR Tulu-3-8B −1.68 +0.47 Keeps REQUEST priority, pulls back toward reasoning on math

Across the full Base → RLVR span, Θ = −1.654 (95% item-paired bootstrap CI [−1.669, −1.638]), negative under both request_first and notes_first orders, and replicated out-of-sample on 352 fresh GSM8K training items (ψ_base = −0.03, ψ_rlvr = −1.72).

The non-monotone step from DPO (−2.15) to RLVR (−1.68) aligns with how each stage is trained. SFT fits single-turn demonstrations that rarely pit conflicting instruction channels against each other, whereas DPO contrasts chosen and rejected completions on instruction-following prompts, rewarding compliance with user directives. RLVR then optimizes exact-answer 0/1 reward on GSM8K and MATH, where obeying a REQUEST to skip reasoning lowers accuracy. Free-generation audits reflect the same math prior: across 576 continuations per stage (64 test items), post-trained models still emit step-by-step reasoning before FINAL: in 569–573 runs even when asked for a direct answer.

3. Confounded Swap Placebos vs. Fixed-Slot Paraphrase Noise

While |Θ| = 1.654 cleared 20% of all_reason vs. all_direct control headroom on the 176-item validation split, it fell below the initial validation swap-placebo bar (2N = 3.63), which swapped two synonymous direct-answer phrasings (placebo_a, placebo_b) between REQUEST and WORKING NOTES. Decomposing a linear slot score into source weights (w_request, w_notes) and directive strengths (d_1, d_2) exposes a structural confound in source-swap placebos: 

S(placebo_a) − S(placebo_b) = (w_request − w_notes) · (d_1 − d_2)
ψ                          = (w_request − w_notes) · (d_reason − d_direct)

Because swapping two slightly unequal phrasings across channels multiplies their wording gap (d_1 − d_2) by the exact same (w_request − w_notes) factor that defines ψ, any checkpoint that strongly privileges REQUEST (w_request >> w_notes) automatically inflates its own swap-placebo. Consistent with that factorization, the largest validation placebo cell (RLVR × notes_first, −1.814) is the exact stage-by-order cell carrying the largest primary conflict effect.

To measure prompt-wording sensitivity without the (w_request − w_notes) source-swap factor, we ran a fixed-slot paraphrase control on 352 untouched GSM8K training items (Base and RLVR), holding source assignment fixed and varying only the reasoning phrasing ("Solve the problem with explicit step-by-step reasoning before the final answer" vs. "Think the problem through one step at a time before giving your final answer"):

Table 2. Fixed-slot paraphrase recalibration on 352 fresh GSM8K training items (Base and RLVR).
Noise aggregation across (slot, order) cells Paraphrase drift N 2N threshold Comparison to |Θ| = 1.654
Median cell drift (N_median) 0.43 0.85 |Θ| > 2N_median
Mean cell drift (N_mean) 0.55 1.09 |Θ| > 2N_mean
Worst single cell (N_max, RLVR × REQUEST) 1.53 3.06 |Θ| < 2N_max

Holding source assignment fixed cuts average placebo drift by more than two-thirds (2N_mean = 1.09 vs. 3.63), yet a single cell (RLVR × REQUEST) still shifts by 1.53 logits between the two synonymous phrasings. The directional Base → RLVR shift is therefore stable across item splits and block orders, while its magnitude (1.65 logits) exceeds typical paraphrase drift (0.43–0.55 logits) without exceeding 2× the worst single-slot wording swing in RLVR.

4. Scope and Diagnostics

  • Single lineage and math-heavy benchmark: All measurements come from Llama-3.1-Tulu-3-8B on GSM8K. Repeating the DPO → RLVR comparison on a second open lineage (such as OLMo-2) and on tasks where direct answers incur no accuracy cost would test whether RLVR relaxes REQUEST binding globally or only when user instructions conflict with outcome reward.
  • Initial mode commitment vs. full generation: At the scored token, explicit_12 separates all_reason from all_direct controls (AUC ≥ 0.80 in all post-trained cells; 0.787 worst-order at Base), and among classifiable post-trained continuations the leading 1/2 token matches downstream format in at least 90% of cases (Base shows 0.62–0.89 format compliance and 4–24% repetition loops; SFT slightly exceeds 1% loops in confirmation generation). Because GSM8K strongly pulls free continuations back into reasoning, S measures initial mode commitment rather than sustained suppression of chain-of-thought.
  • Block-order asymmetry: Θ is negative under both request_first and notes_first orders, with a larger shift under notes_first where REQUEST sits immediately above MODE CHOICE.

Appendix: Checkpoints, Split Locks, and Retired Readout Iterations

A.1 Checkpoints and inference configuration

All four checkpoints share the Llama 3.1 tokenizer vocabulary up to Tulu's added chat template and unused <pad> entry, and all experiments evaluate a byte-identical plain-text prompt without chat templates: meta-llama/Llama-3.1-8B (Base), allenai/Llama-3.1-Tulu-3-8B-SFT (SFT), allenai/Llama-3.1-Tulu-3-8B-DPO (DPO), and allenai/Llama-3.1-Tulu-3-8B (RLVR). Every checkpoint runs in bfloat16 on a single GPU with greedy decoding, explicit <|end_of_text|> EOS and batch-padding IDs, and use_cache=True during generation (overriding the released Tulu RLVR config default of use_cache=False so KV-cache behavior stays identical across stages). Standalone next-token scoring passes discard past_key_values.

A.2 Disjoint salted-hash GSM8K splits

Items are partitioned deterministically via salted SHA-256 ranking (seed = 20260821) in configs/frame_stage_binding_repair_v2.locked.json and configs/frame_stage_binding_recalibration.locked.json:

  • Pilot (24 train items): Compares three single-token mode-choice interfaces (explicit_ra, explicit_12, response_mode_field) across all four stages using choice-token probability mass and all_reason vs. all_direct control separation, blind to request_cue vs. notes_cue source effects. Selected interface: explicit_12.
  • Validation (176 train items): Evaluates explicit_12 on instrument checks (48-item generation subset, 512-token cap) and estimates control headroom H and the initial source-swap placebo constant N.
  • Confirmation (1,319 test items): Evaluates request_cue and notes_cue under both block orders on the complete GSM8K test split, with a 64-item generation audit subset and an independent recomputation check (frame_stage_binding/repair_recompute.py).
  • Paraphrase recalibration (352 train items): Draws 352 untouched GSM8K training items outside the 200 pilot+validation items (Base and RLVR, scoring only) to measure fixed-slot directive wording sensitivity without swapping sources.

A.3 Retired readout iterations

Two earlier prompt/parser pairs failed validation checks on the 24-item pilot before explicit_12 was locked:

  1. Bare R/A sentinel: Prompting Base Llama-3.1-8B to emit a bare R or A produced low candidate-token mass and 4–24% terminal repetition loops under 1,024-token continuations, while one DPO cell frequently jumped straight to reasoning text without emitting the leading letter.
  2. Repair v1 ("Write exactly R or A as the next token" + line-anchored FINAL: parser): Two failure modes appeared in pilot generations. First, SFT obeyed "as the next token" literally on 123 rows by emitting the choice token followed immediately by <|end_of_text|>. Second, requiring FINAL: at line start after an explicit REASONING: header misclassified 165 of 267 RLVR responses that reasoned normally and placed FINAL: mid-line. Repair v2 (explicit_12) replaced the stop-inducing wording with "Start your response with 1 or 2, then continue in that mode" and parsed semantic mode from the last FINAL: marker anywhere in the completion, raising post-trained classifiability to 0.95–1.00.
